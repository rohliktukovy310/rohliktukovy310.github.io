Komplexní průvodce konfigurací a nástroji

Obecné informace

Při procházení adresáři vidíme účet, pod kterým jsme přihlášeni - např.: uzivatel@localhost následuje dvojtečka a za ní jeden ze dvou symbolů: / - root, ~ - domovský adresář - /home/jmenousera. Pokud při procházení nenacházíme některé soubory (například adresář /etc/ se nachází hned za rootem), pravděpodobně musíme přepnout na druhou možnost pomocí cd a / nebo ~.

Příkazy pro každodenní použití (Everyday use)

  • man - vypíše kompletní tutoriál příkazu s všemi jeho přepínači - např.: "man ls".
  • cd - mění adresář.
    • cd .. - vrátí vás o adresář "zpátky".
  • ls - vypíše obsah aktuálního adresáře.
    • -l - vypíše podrobnosti (práva, vlastníka, datum, velikost).
    • -a - zobrazí i skryté soubory (ty začínají tečkou).
  • pwd - vypíše cestu k aktuálnímu adresáři.
  • mkdir - vytvoří v aktuálním místě adresář.
    • -p - v případě, že neexistují nad tím adresářem, který vytváříme.
  • cp - kopíruje soubor či adresář.
    • -r - rekurzivní kopírování.
    • -i - interaktivní režim, ptá se před přepsáním.
  • mv - přesun nebo přejmenování souboru/adresáře.
  • rm (remove) – Smazání souborů.
    • -r - Smaže adresář i s jeho obsahem.
    • -f - Vynucené smazání (bez ptaní). Pozor: Nezvratná operace.

Práce s firewallem

  • sudo firewall-cmd --permanent --add-port=3389/tcp – permanentní otevření portu.
  • sudo firewall-cmd --permanent --remove-port=3389/tcp – permanentní zavření portu.
  • sudo firewall-cmd --list-all - Výpis všech pravidel a nastavení pro výchozí zónu.
  • sudo firewall-cmd --list-ports - Výpis povolených portů.
  • sudo firewall-cmd --list-services - Výpis povolených služeb.
  • sudo firewall-cmd --reload - restartuje firewall.
  • sudo firewall-cmd --state - vypíše stav firewallu.
  • sudo systemctl status firewalld - Zobrazení detailního stavu služby (přes systemd).
  • sudo systemctl start firewalld / sudo systemctl stop firewalld - Spuštění / Zastavení firewallu.
  • sudo systemctl enable firewalld - Povolení startu firewallu po startu systému.

Linux: Nastavení sítě

  1. Při instalaci – nejjednodušší.
  2. Přes nmtui – velmi nespolehlivé – navigace: Tab, Enter, šipky.
    • sudo dnf install NetworkManager-tui.
    • nmtui – zapne nmtui.
  3. Příkazy v terminálu – Lepší než nmtui.
    • nmcli connection show – vypíše síťový připojení.
    • sudo nmcli connection modify "název" ipv4.method manual – přepne z DHCP na manuální statickou adresu.
    • sudo nmcli connection modify "název" ipv4.addresses 172.16.0.254/16 – nastavení adresy a masky sítě.
    • sudo nmcli connection modify "název" ipv4.gateway 172.16.0.2 – nastavení výchozí brány.
    • sudo nmcli connection modify "název" ipv4.dns 8.8.8.8 – nastavení DNS.
    • sudo nmcli connection modify "ens160" ipv4.method manual – nastaví, aby IPV4 byla pouze statická. Bez toho bude mít síťová karta DHCP adresu a tu kterou jsme přidali dohromady.
    • sudo nmcli connection up "název" – restartuje síťovou kartu, aby se nastavení projevilo.

Ověření funkčnosti portů

Pokud "pingujeme" z Windowsu, možností je více, použijeme telnet. Stiskněte Win+R a do nabídky napište optionalfeatures. Tady zaškrtnout telnet políčko a "OK". Pak přes cmd, které je nutné po instalaci restartovat, zadáme příkaz: telnet ipadresa port.

Nastavení LVM

  • sudo pvcreate /dev/sdb /dev/sdc – Physical Volume. Označíme jednotlivé disky pro práci s LVM.
  • sudo vgcreate datavg /dev/sdb /dev/sdc – Volume Group. Spojíme disky do jednoho celku jménem datavg.
  • sudo lvcreate -l 100%FREE -n datalv datavg – Z Volume Group datavg vytvoříme svazek datalv s 100% volného místa.
  • sudo mkfs.xfs /dev/datavg/datalv – Vytvoříme filesystem xfs.
  • sudo mkdir -p /mnt/data – vytvoření prázdné složky – přípojného bodu.
  • sudo mount /dev/datavg/datalv /mnt/data – Svazek připojíme do naší prázdné složky.
  • sudo nano /etc/fstab – Aby se připojení uchovalo, musíme to zapsat do fstabu. Vložíme do fstabu: /dev/datavg/datalv /mnt/data xfs defaults 0 0 – „Při každém startu vezmi tento svazek, připoj ho do této složky, použij formát xfs a výchozí nastavení.“.

Apache Server

  • sudo dnf install httpd - nainstalujeme službu.
  • sudo systemctl start httpd - zapneme službu.
  • sudo systemctl enable httpd - nastavíme její automatické zapnutí při startu systému.

Vytvoření obsahu pro více webů na různých portech

sudo mkdir -p /var/www/web1010/html
sudo mkdir -p /var/www/web2020/html

Těmito příkazy vytvoříme jednotlivé složky pro dva weby na různých portech. Poté musíme do těchto adresářů uložit nějaký obsah na jejich odlišení.

echo "<h1>Web na portu 1010</h1>" | sudo tee /var/www/web1010/html/index.html
echo "<h1>Web na portu 2020</h1>" | sudo tee /var/www/web2020/html/index.html

Takto v nich vytvoříme soubor index.html a vložíme jednoduchý text, který je rozliší.

sudo chown -R apache:apache /var/www/web1010
sudo chown -R apache:apache /var/www/web2020

Nyní musíme nastavit jakožto vlastníka uživatele apache, jelikož když použijeme "sudo" vlastníkem je root a nikdo jiný tam přístup nemá.

Konfigurace Apache

sudo nano /etc/httpd/conf/httpd.conf - Toto je hlavní konfigurační soubor pro všechny weby. V něm musíme nastavit porty, na kterých má Apache naslouchat: Listen 1010, Listen 2020.

/etc/httpd/conf.d - Toto je složka, kde se konfigurují jednotlivé weby na jednotlivých portech. Vytvoříme zde dva soubory: sudo nano /etc/httpd/conf.d/web1010.conf a sudo nano /etc/httpd/conf.d/web2020.conf.

<VirtualHost *:1010> 
    ServerName web1010.cz
    ServerAlias www.web1010.cz
    DocumentRoot /var/www/web1010/html

    <Directory "/var/www/web1010/html">
        AllowOverride all
        Require all granted
    </Directory>
</VirtualHost>

Toto do nich vložíme. Samozřejmě změníme "web1010" v adresářích v druhé složce na "web2020". NEZAPOMENOUT ZMĚNIT PORT V PRVNÍM ŘÁDKU!.

SELinux a Firewall pro Apache

  • Nyní musíme SELinuxu říct, že má pracovat i s našimi porty. Potřebujeme k tomu nástroj: sudo dnf install policycoreutils-python-utils.
    sudo semanage port -a -t http_port_t -p tcp 1010
    sudo semanage port -a -t http_port_t -p tcp 2020.
  • Nyní musíme porty otevřít ve firewallu:
    sudo firewall-cmd --permanent --add-port=1010/tcp
    sudo firewall-cmd --permanent --add-port=2020/tcp.
  • sudo firewall-cmd --reload - FIREWALL RESTARTUJEME.
  • sudo systemctl restart httpd - NAKONEC SLUŽBU RESTARTUJEME. BEZ TOHO SE TO NENAČTE.

Ověření funkčnosti

  • sudo apachectl configtest - Ověří správnost syntaxe v konfiguračních souborech.
  • sudo httpd -S - Ukáže co za porty apache poslouchá a které soubory .conf načítá.
  • sudo semanage port -l | grep http_port_t - Zobrazí porty povolené v SELinuxu.

Nastavení Nginx Serveru

Pokud Nginx nemáme, nainstalujeme si ho: sudo dnf install nginx.

Toto je konkrétní nastavení pro dva různé weby běžící na portech 8080 a 8081. Nejdříve si vytvoříme samotné index.html soubory, které budou weby číst. Musíme je vytvořit mimo /home adresář, jinak SELinux k nim zakáže přístup.

sudo mkdir -p /var/www/web1 /var/www/web2

Tímto vytvoříme složky "web1" a "web2", do kterých dáme soubor index.html, který bude web zobrazovat. Standardně se používá cesta /var/www/. Teoreticky by soubory mohly být umístěny například i v rootu, ale je to bezpečnostní rizko, jelikož bychom nginxu nastavili přístup do celého systému. Zároveň by nás tam SELinux nechtěl pustit.

echo "<h1>Web 1 běží na 8080</h1>" | sudo tee /var/www/web1/index.html
echo "<h1>Web 2 běží na 8081</h1>" | sudo tee /var/www/web2/index.html

Tyto dva příkazy do našich adresářů nahrají text odlišující dva weby. Lze to samozřejmě udělat i ručně.

Konfigurace Nginx

Nyní musíme nakonfigurovat Nginx a říct mu, kde si má soubory vzít: /etc/nginx/conf.d/ - v této složce si vytvoříme dva soubory pro dva weby, které budou určovat jejich nastavení (Např.: web1.conf a web2.conf). Nyní do těchto dvou souborů vložíme konfiguraci (samozřejmě nezapomeneme změnit porty a soubory pro jednotlivé weby):

server {
    listen 8080;
    root /var/www/web1;
    index index.html;
}

Po uložení si můžeme nastavení zkontrolovat pomocí sudo nginx -t. Pokud zde budeme mít nějaké syntatické chyby, upozorní nás to.

Porty, Firewall a SELinux

Teď si otevřeme porty, na kterých chceme weby provozovat (jestli to už nemáme).

  • sudo firewall-cmd --permanent --add-port=8080/tcp
  • sudo firewall-cmd --permanent --add-port=8081/tcp
  • sudo firewall-cmd --list-all - Pro kontrolu
  • sudo firewall-cmd --reload

Nastavíme porty také pro SELinux:

  • sudo semanage port -a -t http_port_t -p tcp 8080
  • sudo semanage port -a -t http_port_t -p tcp 8081

Protože SELinux je přísný, musíme mu říct, že ty soubory jsou určený pro nginx web. Těmito příkazy to uděláme trvale:

# Trvalé zapsání do databáze SELinuxu
sudo semanage fcontext -a -t httpd_sys_content_t "/var/www/web1(/.*)?"
sudo semanage fcontext -a -t httpd_sys_content_t "/var/www/web2(/.*)?"

# Aplikace štítků na existující soubory
sudo restorecon -Rv /var/www/

Jako poslední musíme Nginxu nastavit práva pro práci se soubory, co má zobrazit:

sudo chmod -R 755 /var/www/web1
sudo chmod -R 755 /var/www/web2

Konkrétně mu nastavíme read a execute. Execute proto, aby se prokousal přes adresáře až k souboru a read, aby si ho přečetl a zobrazil. Nakonec službu restartujeme: sudo systemctl restart nginx. Abychom mohli měnit bezpečnostní kontexty pro SELinux, nainstalujeme si k tomu nejdřív nástroj: sudo dnf install policycoreutils-python-utils.

Vzdálený přístup

Servery a klienti: Server - Aplikace, do které se připojujeme (Ovládaný PC). Klient - Aplikace, přes kterou se připojujeme (Ovládající PC).

Remmina

Linux klient pro RDP, SSH, VNC. Funguje jako jedna aplikace, do které se doinstalovávají moduly pro jednotlivé protokoly.

  • sudo dnf install remmina.
  • sudo dnf install remmina remmina-plugins-vnc – nainstaluje remminu i s modulem VNC.

SSH + SSH klíče

  1. Na Windows 11 otevřete Příkazový řádek a napište ssh-keygen. Vygeneruje se veřejný a soukromý klíč. Když se bude terminál ptát na heslo pro autentizaci SSH klíče, tak musíme zmáčknout pouze enter – nechat ho prázdné (pokud chceme ověřování bez hesla). Kdybychom heslo nastavili, tak by se při každé autentifikaci certifikátem terminál ptal i na heslo.
  2. Veřejný klíč nyní musíme umístit do souboru authorized_keys. Tento soubor musí být v adresáři ~/.ssh/. ~/ - zástupný znak pro domovskou složku, .ssh – tečka před složkou znamená že složka je skrytá. Vytvoření: mkdir -p ~/.ssh, nano ~/.ssh/authorized_keys.
  3. Na Linuxu v souboru /etc/ssh/sshd_config změňte PasswordAuthentication z „yes“ na „no“ a restartujte službu SSH. Nyní se přihlásíte pouze s klíčem.

SSH přihlášení: ssh jmenousera@ipadresa – např: ssh uzivatel@172.16.0.199. Nejdříve se musíme přihlašovat pomocí hesla usera, za kterého se přihlašujeme. Po nastavení ssh certifikátu už ne.

RDP (Remote Desktop Protocol)

  • Windows RDP klient: Je nativně nainstalovaný a zapnutý.
  • Windows RDP Server: Je nativně nainstalovaný, ale je nutné ho zapnout. Ve Windows 11 jděte do Nastavení > Systém > Vzdálená plocha (Remote Desktop). Přepněte přepínač Vzdálená plocha na Zapnuto a potvrďte.
  • Linux RDP Server: sudo dnf install xrdp.
  • Linux RDP Klient: Řešíme přes Remminu: sudo dnf install remmina remmina-plugins-rdp.

Připojení z Windows na Linux

Ve windowsu nativně – není nutno instalovat. Na linuxu musíme nainstalovat. Například xrdp: sudo dnf install xrdp, sudo systemctl enable --now xrdp. Dále: sudo firewall-cmd --permanent --add-port=3389/tcp, sudo firewall-cmd --reload. Pokud to nefunguje, doinstalujte: sudo dnf install plasma-workspace-x11 xorg-x11-xinit.

Připojení z Linuxu na Windows

Zapněte vzdálenou plochu ve Windows 11. Na Linuxu nainstalujte sudo dnf install remmina remmina-plugins-rdp, spusťte Remminu. Vyberte RDP, zadejte IP adresu Windows, uživatelské jméno a heslo do Windows. Chybějící certifikát stačí "Přijmout".

VNC

  • Linux VNC klient: Řešíme přes Remminu: sudo dnf install remmina remmina-plugins-vnc.
  • Linux VNC server: TigerVNC: sudo dnf install tigervnc-server.
  • Windows VNC server: TightVNC.
  • Windows VNC klient: RealVNC Viewer.

Připojení z Linuxu na Windows

Nainstalujte Remminu s VNC modulem a otevřete port 5900 (sudo firewall-cmd --permanent --add-port=5900/tcp, reload). Na Windows stáhněte TightVNC, nainstalujte Server a nastavte heslo. Jděte do Remminy, vyberte VNC, zadejte IP a heslo.

Připojení z Windowsu na Linux

sudo dnf install tigervnc-server, vytvořte heslo pomocí vncpasswd. Musíme systému říct, že "Displej číslo 1" patří vašemu uživateli. Otevřete konfigurační soubor sudo nano /etc/tigervnc/vncserver.users a na konec přidejte :1=uzivatel (bez hashtagu). Otevřete port 5901 (sudo firewall-cmd --permanent --add-port=5901/tcp, reload).

SCP, SFTP a FTP

SCP a SFTP

Protokoly pro kopírování souborů pracující přes SSH. WinSCP - Windows klient pro SCP i SFTP (stačí stáhnout a nainstalovat). Zadává se Hostitel, Uživatelské jméno, Heslo. U SCP i SFTP číslo portu 22 (SSH).

OpenSSH Server: V Linuxu většinou předinstalovaný (Fedora). Ve Windowsu nutno nainstalovat (Aplikace -> Volitelné součásti -> Zobrazit funkce -> Server OpenSSH) a nastavit typ spouštění na "automaticky" v "services.msc". V Linuxu instalace: sudo dnf install openssh-server.

FTP

FTP Windows Server

Stáhnout Filezilla server a nainstalovat. Nutno povolit ve firewallu soubor filezilla-server.exe. V konzoli "Administer FileZilla Server" vytvořit nového uživatele. Připojíme se přes heslo z instalace. Pokud je zde již "<system user>", můžeme se přihlásit přes uživatele ve Windowsu. V Server -> Configure -> Users -> Add (User) vytvoříme nového. virtual path je to, co uvidíme po připojení (Pro Linux se dává /). native path je skutečná cesta. Nezapomenout nastavit práva.

FTP Klienti

  • Windows klient: Filezilla (má GUI, podporuje i SFTP). Lze se připojit i přes průzkumníka souborů zadáním ftp:\\adresastroje do adresního řádku nebo v záložce síť "nové místo pro připojení". Nutné znát username a heslo.
  • Linux klient: sudo dnf install filezilla. Ovládá se v GUI.

FTP Linux Server

vsftpd - very secure FTP Daemon.

sudo dnf install vsftpd
sudo systemctl enable --now vsftpd

Povolíme a zapneme vždy při startu. Konfigurace je uložena v /etc/vsftpd/vsftpd.conf. Musí být odkomentováno/přidáno:

  • anonymous_enable=NO
  • local_enable=YES
  • write_enable=YES
  • chroot_local_user=YES
  • Na konec: allow_writeable_chroot=YES

Poté: sudo systemctl restart vsftpd, pro SELinux sudo setsebool -P ftpd_full_access 1 a přidat do firewallu sudo firewall-cmd --add-service=ftp --permanent, reload. Nyní se lze připojit například z Windows přes Filezillu.
